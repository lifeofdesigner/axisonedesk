# CREATE_EVENT

Extends [_GENERIC_CREATE_WORKFLOW.md](_GENERIC_CREATE_WORKFLOW.md).

## Purpose
Record a domain event (e.g. order status changed, ticket message posted) for audit trail, notification triggers, or downstream automation — following the pattern established by `order_events` (`0004_orders.sql`) and `audit_logs` (`0010_platform_admin.sql`).

## Workflow (delta)
1. Prefer a Postgres trigger function (see `log_order_status_change()` in `0004_orders.sql` for the real example) over client-side event logging — events tied to a DB state change should be generated by the DB, not trusted from the client.
2. If the event should also generate a user-facing notification, call into the existing `notify_org_members(...)` RPC pattern (`0019_notifications.sql`) rather than building a parallel notification path.
3. Platform-wide audit events use `log_audit_event(...)` (`0010_platform_admin.sql`) — don't create a second audit table.

## Documentation Updates (delta)
Note the new event type in the relevant module's section of [docs/04_MODULES/INDEX.md](../04_MODULES/INDEX.md).
